## 1.0.4：动画播放与阶段开销

连续操作的布局、标题和原生阴影准备期间，旧动画仍在播放。新实现保留原轨迹，准备完成后按合成器预计交接帧重新采样，再让新曲线从同一时刻继续。85 ms 人工准备延迟的原生像素测试中，旧版三次倒退 330–352 px；新版没有倒退。曲线形状、用户设置时长及无弹性过渡保持不变。

原生阴影由四块互不重叠的边缘组成，直接将透明度应用到各块，不再先创建整窗大小的中间混合层。重新展开完成后，零透明度阴影从活动合成树摘下，保留资源供下次退出复用。动画期间才申请系统动态合成升频，完成或取消时释放；没有逐帧 CPU 循环、抓屏循环或计时器精度修改。

逐轮统计数据：[animation-flow-20261114.csv](benchmarks/animation-flow-20261114.csv)。

### 当前会话的逐阶段测量

2026-11-14，64 位、1000×640 像素虚构场景，32 个已显示但放置在屏幕外的原生源窗口，320 ms 测试动画，每轮连续运行四个循环。改动前为本机上一版系统优化源码；改动后为本次完整动画优化。32 窗口分别记录三轮与两轮，全部保留。用户实际安装的动画时长不被测试修改。

当前会话的合成统计只报告一个 AMD 输出，周期约 16.6984 ms（59.886 Hz）。硬件列表中的 160 Hz 外接屏没有出现在本次呈现目标中；本表不代表 160/240 Hz 实测。通过完成帧的目标统计与实际 present 计数去重计算呈现间隔，读取完整帧历史，没有全屏录制。FPS 是各动画有效时间段内平均呈现间隔的倒数；它属于整个输出的 DWM 呈现节奏，并非窗口程序独占帧率，也不是动画提交耗时。

| 32 窗口阶段 | 修改前 FPS 范围 | 修改后 FPS 范围 | 修改后 P95 间隔 |
| --- | ---: | ---: | ---: |
| 展开 | 59.9 | 59.0–59.9 | 16.7 ms |
| 重排 | 59.0–59.9 | 59.9 | 16.7 ms |
| 退出 | 49.0–52.5 | 58.0–58.1 | 16.7 ms |
| 中途反向重新展开 | 59.9 | 59.0–59.9 | 16.7 ms |

退出阶段的每轮 FPS 中位数从 49.6 提高到 58.1，P95 间隔从 33.4 ms 降到 16.7 ms。每四次退出中，大于 1.5 个刷新周期的间隔由 6–11 次降至 2 次；新版最长间隔仍约 33.4 ms，因此不是零长帧。12 窗口首轮中展开与重排均为 59.9 FPS，退出 57.2 FPS、反向 59.0 FPS，仍受其他桌面工作影响；不能声称所有阶段始终满刷新率。静止停留与选框切换按事件更新，不用持续 FPS 判断空闲流畅度。

### 瞬时资源

资源约每 50–65 ms 采样，覆盖场景准备、播放、停留和清理；更短尖峰可能未被捕获。CPU 从进程累计时间中减去采样线程累计时间，数值受约 15.6 ms 记账粒度影响；100% 单核表示占满一个逻辑核，当前机器 32 个逻辑处理器。测试进程包含虚构源窗口和采样器，内存不是已安装 Windhawk 宿主的完整占用。场景准备从图形设备已经就绪后开始，不包含完整冷启动。

32 窗口新版两轮的峰值：场景准备约 108% 单核（折合整机约 3.4%）；主要播放阶段约 31% 单核（整机约 1%）。进程私有内存不超过 40.4 MiB、工作集不超过 61.1 MiB，进程本地 GPU 分配约 18.2 MiB。私有内存与本地 GPU 分配相比旧版没有明显下降，不声称内存节省。

DWM 另计：退出阶段最忙 GPU 引擎的每轮峰值中位数约 68.4% → 51.8%，P95 中位数约 65.5% → 49.4%。这里是对应进程所有 GPU 引擎中的最大值，不是各引擎之和，不等于整卡总利用率；DWM 数值含其他桌面工作。受进程访问权限限制，本轮没有得到可信的 DWM CPU 与内存读数。采样器每轮自身消耗约 0.7–1.0 秒 CPU，主要来自性能计数器初始化和采样，不属于产品常驻开销。

本次空闲检查经过资源回收后再观察 20 秒：CPU 记账增量 0 ms、I/O 为 0，没有待触发计时器，任务栏工作线程已退出；自动模式保留图形设备，省内存模式已确认释放设备。这不是进程内存为零的声明。

### 验证与依据

原生阴影四边与外角的像素差为 0。三种缩放、三种透明度的全区域比较中，直接透明度模式相对原分层模式最大通道差为 1/255；原生任务栏四边裁剪、最小化恢复、反向动画与图形引用释放检查通过。原生像素测试确认重新提交没有向后跳变；时间轴测试覆盖准备延迟、标题、圆角、任务栏、阴影缓存及临时升频请求的释放。

实现与计量依据：[合成帧状态](https://learn.microsoft.com/en-us/windows/win32/api/dcomptypes/ne-dcomptypes-composition_frame_id_type)、[目标呈现统计](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-dcompositiongettargetstatistics)、[透明度模式](https://learn.microsoft.com/en-us/windows/win32/api/dcomptypes/ne-dcomptypes-dcomposition_opacity_mode)、[动态合成时钟请求](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-dcompositionboostcompositorclock)。

## 本地开发版：新增窗口与连续交互

新增窗口的显示通知按已排队的批次处理：先绑定全部新画面，再进行一次重排、标题绘制和动画提交。此前虽然外层收集了通知，内部仍逐个求解、绘制并等待提交。重复状态通知和任务栏通知也合并；任务栏快照没有改变最小化栏排序时不求布局，但会更新返回按钮的位置。

2026-11-14 同机、64 位、屏幕外虚构原生窗口，每组运行三次。下表为处理中位数，单位毫秒；窗口已由另一个进程创建并显示，计时从显示通知排队完成后开始，至画面接入、布局、标题、动画提交及必要的首次显示等待结束。

| 原有窗口 / 同批新增 | 优化前 | 优化后 | 重排次数 |
| --- | ---: | ---: | ---: |
| 8 / 4 | 65.29 | 18.37 | 4 → 1 |
| 16 / 8 | 297.60 | 34.54 | 8 → 1 |
| 32 / 16 | 583.41 | 34.34 | 16 → 1 |

各窗口带三条重复显示通知，测试包含保留手势选择及其选框。优化后九组场景的已有预览路径与最终布局均通过分离检查。以上不是应用启动时间、动画播放时长、屏幕首帧延迟或 FPS；大量窗口场景的收益也不能直接推算到普通单窗口操作。

同一组场景中，连续 100 次未改变的任务栏通知处理从约 0.15–0.49 ms 降至 0.007–0.015 ms（首组冷调用除外）。这一项主要消除无效求解，本身不是主要耗时。

交互回归覆盖统一时刻采样、手势选中项保留与消失后的回退、拖出或取消捕获后的左键释放、任务栏按钮位置变化、真实跨进程标题更新，以及动画中改名不重启时间轴。标题通知使用 [Windows 原生名称变化事件](https://learn.microsoft.com/en-us/windows/win32/winauto/event-constants)，只在总览打开期间订阅；重复且未改变的标题不重绘、不提交。原有单段平稳动画、原生阴影和任务栏裁剪保持原样。

## 本地开发版：批量关闭与退出准备

中键关闭与 Shift＋中键同应用批量关闭使用原生关闭请求。已排队的隐藏、销毁通知合并后只做一次重排，重复通知不再重复求解；没有窗口被移除的显示器保留原有目标位置。

退出阴影优先复用窗口内容已经校验过的源矩形。当前外框与可见边框相符时不重复调用 DWM 尺寸查询；尺寸改变时重新查询、重建阴影。阴影透明度、缩放与任务栏的相同延迟动画共享合成对象。

同机、单屏场景，使用已显示但放在屏幕外的虚构原生窗口，各测量三次，中位数如下。单位为毫秒，每格为优化前 → 优化后。

| 窗口数 | 首次退出准备 | 同一场景再次收回 | 关闭一半窗口的通知处理 |
| --- | ---: | ---: | ---: |
| 16 | 7.48 → 5.58 | 3.47 → 1.64 | 23.20 → 4.68 |
| 64 | 29.21 → 18.00 | 13.57 → 4.47 | 173.02 → 10.79 |
| 128 | 60.58 → 36.01 | 28.16 → 9.35 | 4068.45 → 50.27 |

“首次退出准备”包含原生阴影建立和动画提交；“再次收回”复用同一场景的阴影，模拟收回被打断后重试，不是跨总览打开周期保留阴影。“通知处理”从窗口已经销毁、消息已经排队后开始计时，包含重排和合成提交，不含应用响应关闭、保存提示及动画播放时间。以上不是屏幕首帧延迟或 FPS。

优化后九组场景中，每条保留窗口路径在起点、终点及三个中间位置均无重叠。原生阴影四边及外角像素差仍为 0；尺寸变化重新采样、最小化恢复及反向动画检查通过。32/64 位中键测试覆盖跨进程、同进程不同应用身份、真实关闭事件、取消关闭及拖动取消。

自动模式闲置清理后采样 20 秒，CPU 时间增量为 0 ms、I/O 为 0，没有待触发定时器，任务栏读取线程已停止；图形设备和有容量上限的壁纸缓存仍保留。省内存模式确认释放图形设备。这些是本机采样结果。

## 0.5.8 位置与尺寸使用相同缩放比例

以可用区域中心为基点，将源窗口中心的偏移乘以窗口缩放比例，再进行位置求解和候选评分。窗口缩到 50% 时，原来相距 2000 像素的两个中心，其目标距离改为 1000 像素。实际位置仍受边界、标题间距和动画路径约束，不能由这个目标距离推断所有场景的最终覆盖率。

已显示的预览位置用于约束连续操作的运动路径，直接使用当前坐标，不重复缩放。

## 0.5.7 局部重排

最小化和关闭窗口后，先保留已经验证能放下的旧比例，再搜索更大的可行布局。局部移动的距离不设硬性上限；小场景降低旧位置的权重，并细化缩放比例。已有预览继续保留分离运动路径，底部区域高度变化时也不再丢弃这些关系。动画中再次操作时，以当前采样位置判断路径。

用修改前生成的同一组 596 个最小化场景检查新旧算法，其中 498 个场景的旧布局仍放得下：不必要的缩小从 87 次降为 0，新的布局全部满足边界、间距及分离路径检查。普通窗口内容占上方区域的平均比例从 40.31% 增至 41.34%。这不是逐场景都变大或全局最优的保证；底部区域变高、或需要避免运动交叉时，比例仍可能受限。

240 组连续最小化的中途打断检查通过；32/64 位构建各通过 39 项布局、76 项原生预览和 4 项中途重新展开检查。原生画面恢复时主体像素最大通道差为 0，清理后 DComp/D3D 设备引用为 0/0。上述结果来自固定几何场景与隔离虚构窗口，不代表屏幕帧率或所有第三方应用组合。

## 0.5.6 再次打开

每次重新打开都重新计算布局，包括收回动画尚未结束时再次展开；局部调整产生的坐标只用于连续操作。60 组先局部删窗、再重新打开的检查中，新结果均与直接求解一致。中途反向时也重新求目标位置，并在计算完成后采样当前动画位置，避免倒退。

双屏、12 个隐藏虚构窗口的隔离测试中，触发闲置清理后再次准备场景，7 次测量的中位数如下：

| 阶段 | 0.5.5 | 0.5.6 |
| --- | ---: | ---: |
| 壁纸准备 | 184.88 ms | 0.29 ms |
| 场景准备至合成提交完成 | 301.94 ms | 69.27 ms |

这里直接调用闲置清理流程，比较其对下次准备的影响，不含热键接收、真实窗口枚举与屏幕首帧。不是完整操作延迟或 FPS 测量。自动、常驻模式在闲置后保留最多 64 MiB 壁纸像素缓存；这是像素容量上限，不是进程或驱动总内存上限。

## 0.5.5 大量窗口与后台开销

- 大量窗口的候选布局复用真实方位权重，用评分上界提前排除不可能胜出的候选；删除已经被更长路径蕴含的冗余间距约束。保留自由坐标、窗口面积权重、统一缩放与运动分离规则，小场景的独立参考坐标保持一致。
- 文字、宽度、DPI 与连接圆角未变时复用标题表面和图层；同 DPI 的字体格式复用。500 条连续位置通知按最终真实尺寸合并处理，不增加轮询或延迟定时器。
- 每个显示器复用壁纸表面；缓存命中时仅检查文件时间戳，不重复枚举系统壁纸。显示器、设置与主题通知使缓存失效。窗口层次使用索引更新，顺序未变时不重建图层树。
- 未选中的窗口不创建选框和按钮相关的五个合成对象，也不提交它们的动画。动画中首次悬停时，装饰加入原来的绝对时间轴。相同动画的查询改为索引，避免大场景逐条扫描。
- 后台采用事件等待，动画一次性提交给 DWM。关闭总览会解除窗口事件钩子；60 秒后关闭任务栏读取线程，保留排序快照供下次直接使用，再异步刷新。0.5.5 同时清空壁纸缓存，0.5.6 改为上述有容量上限的缓存。自动模式保留设备以便快速展开，省内存模式释放设备并回收工作集。

## 回归范围

0.5.5 的 32/64 位构建各通过 39 项布局检查、76 项原生预览检查，最终 DComp/D3D 设备引用为 0/0。任务栏排序、手势交互、原生圆角像素检查和独立版自检通过。本机已验证独立版连接 Explorer 及两种位数的 Windhawk 模组实际加载。

这些结果来自开发机器与隔离测试窗口，不代表全部 Windows 版本、驱动或第三方应用组合。
